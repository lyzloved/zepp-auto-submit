### 原网站兑换接口

```text
POST https://zepp.net.cn/ajax.php?act=kmsq
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
qq=<账号>&pwd=<密码>&km=<卡密>
```

公开网页兑换函数 `_0x2cee26` 使用上述三个字段，code 0 表示兑换成功，其他值表示失败。新版兼容数值或字符串 0。卡密按原网页规则去除空白与 ASCII 圆括号内备注，随后进行 URL 表单编码。账号去两端空白，密码保留输入的原文和特殊字符（网页会 trim 密码，新版避免改变密码）。

这是第三方网站的卡密兑换，并非微信或 Zepp 官方 API。仅兑换用户提供的有效卡密，不生成卡密、不绕过服务端校验。

新增 17 项兑换协议检查，验证字段、编码、卡密清理、空输入和返回码。连同原检查合计 72 项通过。已重新编译 APK，确认签名与前版一致、versionCode 为 3，支持覆盖升级。未进行真机安装或真实卡密兑换，也未验证微信实际同步。

### 原网站到期查询实现

2026-10-27 重新下载公开脚本，与前次读取版本的 SHA-256 一致。原网页 `getExpireDate` 和到期查询入口调用：

```text
POST https://zepp.net.cn/ajax.php?act=check_qq
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
qq=<表单编码后的 Zepp 账号>
```

该接口只发送账号，不发送密码或卡密。网页逻辑：code 0 从 msg 的 `会员未到期:日期时间` 提取有效期；code 2 表示封禁；code 3 表示会员已过期；其他结果为未知。客户端兼容字符串和数字返回码，并按纯文本处理结果。

新版额外严格校验日期，拒绝不存在的日期，查询失败或响应不明时显示“暂无法确认”，不伪造到期时间，也不把查询错误当成过期。无时区的日期按北京时间解释；本地倒计时依赖手机时间，服务端的实际权益判定仍由原网站负责。过期响应没有提供具体时间时，会明确显示未提供。

32 项新增模拟协议检查涵盖：返回码映射、表单编码、北京时间转换、日期合法性、过期边界、3 天提醒边界及剩余时长。与原 23 项提交协议检查合计 55 项通过，均不使用真实账号和网络提交。

## 安装和使用

1. 将 `StepSubmit-1.4.1.apk` 下载到 Android 6.0 或更高版本手机，允许此次安装来源后安装。
2. 在 Zepp 中提前完成微信运动绑定。绑定方法及可用性以 Zepp 当前实际页面为准。
3. 输入自己的 Zepp 账号、密码和目标步数；有效期检查仅需账号。安装包没有内置截图中的账号密码。
4. 可勾选“加密记住账号和密码”。此后打开应用、点击“立即提交”即可。
5. 应用每次点击发起一次请求，不会在启动时自动提交，也不会开启网站的每日定时任务。
6. 后端返回成功后，请自行打开微信运动确认。目标步数低于当前步数可能不会同步。

请求超时后不自动重试，因为服务器可能已经处理了请求。先检查微信运动，再决定是否重试。

## 实际接口分析（2026-10-27）

分析来源是公开页面和它实际引用的 JavaScript：

- 页面：https://zepp.net.cn/
- 提交脚本：https://zepp.net.cn/assets/js/index.js?yyd12
- 脚本中的提交函数 `_0x706c3c` 使用 jQuery AJAX。
- 这不是微信官方提交接口；第三方服务内部如何调用 Zepp、保存凭据或实现同步，无法从公开前端确认。

### 请求

`POST https://zepp.net.cn/ajax.php?act=yd`

Content-Type: `application/x-www-form-urlencoded; charset=UTF-8`

| 字段 | 来源及含义 | 本应用行为 |
| --- | --- | --- |
| account | Zepp 邮箱或手机号 | 用户输入，去除两端空白 |
| password | Zepp 密码 | 用户输入，保留特殊字符和空白，进行表单编码 |
| steps | 目标步数 | 整数，范围 1–98800 |
| motic | 执行模式：0 手动、1 自动、2 递增 | 固定 0，仅单次提交 |
| api | 源码仍有读取逻辑，但页面对应下拉框已注释 | 和当前网页实际序列化行为一致，省略该字段 |

示意请求（全部为虚构值）：

```text
account=user%40example.test&password=example-only&steps=15570&motic=0
```

前端没有在此提交函数中附加 Authorization、Bearer token 或 CSRF token。该观察仅针对公开前端，不代表后端没有其他访问限制。应用设置 Origin、Referer 和 X-Requested-With，并使用系统默认 HTTPS 证书校验，禁止自动跟随重定向。

### 响应与限制

公开前端以 JSON 的 `code == 200` 判定接受请求，以 `msg` 展示说明。HTTP 200 本身不能代表业务成功。客户端接受数值 200 或字符串 "200"，其他代码均显示失败；成功状态明确提醒检查微信运动。

脚本另有 `/ajax.php?act=qwe` 配置请求及本地四位验证码弹窗逻辑。本次不含账号的配置请求返回 `{"code":-2,"msg":"未知请求"}`，因此无法确认该配置功能当前是否可用。应用不伪造验证码、Cookie、卡密或付费权限；如服务返回验证或权益要求，应按服务方正规流程处理，客户端不能保证绕开这些要求。

### 账号密码处理

- 密码发往 `zepp.net.cn`，由该第三方后端处理；应用并非直接向微信上传。
- 未勾选记住时不持久化账号密码；勾选后，以 Android Keystore 管理的 AES-GCM 密钥加密保存到应用私有存储。
- 关闭备份，无广告、统计 SDK、明文凭据日志或外部存储权限。
- 屏幕和最近任务预览受 FLAG_SECURE 保护；不支持系统截图。
- 清除按钮删除本机保存信息；不会删除服务端可能保留的数据。
- 服务结果按纯文本显示，并遮蔽结果中直接出现的当前账号密码。
